# Linux 发行版适配与真实 VPS 验收计划

日期：2026-11-22。状态：2.0.3 测试版已发布；Ubuntu 22.04 真实 VPS 的基础与图形检查通过，账号交互、重启、长期运行及完整更新回归待验收，其余三个新增目标尚未放行。

2.0.3 测试版安装器接受 Debian 12 和 Ubuntu 22.04 LTS amd64；旧 2.0.2 包仍只面向 Debian 12，不能直接用于 Ubuntu。按用户本轮授权，将之前的 ClaudeDesktop、安装输出和 Ubuntu 适配改动一并发布为测试版，不提升为正式版。

## 范围

目标为 Debian 12、Debian 13、Ubuntu 22.04 LTS、Ubuntu 24.04 LTS、Ubuntu 26.04 LTS，架构仅 amd64（x86_64）。Ubuntu 只覆盖列出的 LTS 版本，不包含中间的非 LTS 发行版。

用户提供一台可轮流重装上述系统的专用测试 VPS。使用系统原有的内核、systemd 和软件源进行验收；WSL2、容器和 CI 结果只能补充证据，不能代替真实 VPS。

按用户 2026-11-22 的补充要求，优先直接在测试 VPS 修改与测试，减少本机 WSL 的重复安装和依赖下载；WSL 只用于必要的发行构建和少量本地检查。

沿用普通运行用户 `claudeweb`，root 仅处理安装、更新等系统操作。保留「设置 → 关于 → 检查更新 → 更新」、签名校验、数据目录和现有资源策略。适配不通过关闭 Chromium / Electron 沙箱或全局放宽权限来规避问题。

## 实施顺序和完成条件

### 1. 平台识别与依赖整理

- [ ] 精确接受上述五种 `/etc/os-release` 组合和 x86_64；拒绝未验证的系统与架构，不仅根据 `ID_LIKE=debian` 放行。
- [ ] 列出基础工具、图形运行、中文输入、钥匙串和 APT 源的各版本依赖，核对包名及仓库是否默认启用。
- [ ] 将平台差异集中管理，安装、修复和更新不得维护相互冲突的包清单；一行下载安装入口仍可独立执行。
- [ ] 保留现有信任链，不为共享适配代码额外执行未校验的远程脚本。
- [ ] 补充有意义的识别验证：五种允许平台、版本相近但未支持的系统、非目标架构、缺失系统信息；不能只改允许列表后视为完成。

完成条件：能解释每个目标的依赖来源和安装方式；不支持的环境在修改系统之前给出明确原因。

### 2. 发布包与运行时兼容

- [ ] 核查 Node.js、终端 PTY、SQLite、密码验证等原生组件的动态库需求，首先验证现有候选包在 Ubuntu 22.04 的加载情况。
- [ ] 优先验证 Ubuntu 22.04 作为五系统共同构建基线的可行性；以真实依赖检查与运行结果决定，不直接假定现有 Debian 12 包通用。
- [ ] 优先维持一份 `linux-x64` 发布包；若共同包确实无法覆盖，则先说明具体阻碍，再设计按平台选包与签名清单，不能偷偷改变更新协议。
- [ ] 同步本地构建、CI、发布工作流、包内元数据和发布说明；已有已发布包保持不变。
- [ ] 对固定的 Playwright 版本验证五系统依赖解析与实际启动，不能用最新版文档代替锁定版本的测试。
- [ ] 验证 ClaudeDesktop 官方签名 APT 包在各系统的安装与启动；记录实际包版本及签名校验结果，失败时不能把完整功能标为通过。

完成条件：同一候选提交与发布包能在五系统加载原生模块、启动服务；图形应用仍保留自身沙箱。构建基线调整后先补做 Debian 12 回归。

### 3. 建立可重复的验收材料

- [ ] 准备固定的非敏感数据样本：项目文件、聊天、引用、记忆、插件设置及数据库记录；记录更新前后的校验依据。
- [ ] 整理安装、重装修复、图形生命周期、重启、更新、回滚及数据保留的执行入口，标明哪些脚本会删除服务或测试数据。
- [ ] 保存候选提交、包 SHA-256、测试脚本版本和依赖版本；测试中途改包后，重新测试所有受影响系统。
- [ ] 对各平台记录系统和内核版本、架构、systemd 状态、实际资源、磁盘与 inode、监听地址、最终服务属性和进程树。
- [ ] 沿用临时测试签名清单进行未发布包的升级与失败回滚测试；生产签名私钥不上传 VPS，不替换公开稳定清单。

当前尚无正式版：允许使用本地测试基线验证更新协议，但必须记录为测试构件。不能把仅改版本号的构件更新写成「已从真实上一正式版完成网页更新」。正式版出现后补做真实版本升级。

### 4. 真实 VPS 五轮验收

建议顺序：**Debian 12 → Ubuntu 22.04 → Ubuntu 24.04 → Debian 13 → Ubuntu 26.04**。先建立现有基线，再验证共同构建包在较早 Ubuntu 环境中的兼容性，之后覆盖其余系统。若 VPS 当前已经是某个目标版本，可先在当前版本建立结果，再安排重装。

每轮执行：

1. 确认测试目标及 SSH 连接，记录新系统版本；重装由用户通过厂商控制台操作。旧机器的连接信息和 SSH 指纹不能直接当作重装后的现场事实。
2. 从干净系统安装同一候选包，验证安装阶段输出、密码不进日志、重复安装修复和失败重试。
3. 验证网页登录、项目、文件、终端及 Claude CLI 的真实会话、中文输入、停止和再次生成。
4. 验证浏览器与 ClaudeDesktop 启动、同时运行、中文输入、剪贴板、最小化与橙点、恢复、全屏、关闭和启动中取消。
5. 检查关闭后的进程组、临时目录、缓存与 inode；登录资料和钥匙串仍保留，不能要求总 inode 回到不考虑持久数据变化的固定数值。重复启动关闭观察有无持续增长。
6. 验证 SSH 隧道、IPv6 禁用、认证、sudo 确认及权限；使用真实 Cloudflare 测试域名时，单独记录隧道与域名结果，模拟接口不算真实接入通过。
7. 使用专用测试清单，从网页执行更新、重连与结果显示；模拟坏版本检查自动恢复，并验证手动回滚、项目与登录配置保留。
8. 重启 VPS，验证服务和已配置隧道的恢复；检查图形应用能重新打开。重启会终止原有图形进程，不要求保留其内存中的窗口状态。
9. 在指定的长时间运行窗口观察内存、日志、进程、缓存与 inode；记录实际持续时长，不把短测写成长测。最后才执行会卸载产品的测试。
10. 取回本轮日志和结果，检查内容不含密码、Token 或账号登录资料；材料保存在本机 E 盘，确认保存后再进行下一次重装。

账号登录需要用户完成交互；没有登录就只能记录「登录页可用」，不能标记已登录后功能通过。任何需要真实模型、用户凭据或外部服务的项目单独记录，不由启动成功推断。
